# 工资条发送系统（Vue 3 + Node/Express + TypeScript）

浏览器里完成「导入工资表 → 预览 → 批量/单个发送 → 发送留痕」的全流程。

## 快速开始

Windows 最简单：双击 **`启动调试.bat`**（开发模式）

- 自动读配置里的端口（不写死）、自动装依赖、起服务、8 秒后自动打开浏览器
- 关掉窗口即停止；改代码前后端都会自动生效

命令行：

```bash
cd salary-web
npm install          # 安装依赖
npm run dev          # 开发模式：前端 + 后端一起起
```

端口从配置读取，改哪边都行：

| 服务 | 端口来源 | 当前值 |
| --- | --- | --- |
| 前端 | `package.json` 里 `vite --port` → `vite.config.ts` 的 `server.port` → 5173 | **8000**（见 `vite.config.ts`） |
| 后端 | `.env` 里的 `PORT=` → 环境变量 `PORT` → 3001 | **3001** |

正式使用（单进程、构建后托管）：

```bash
npm run build        # 类型检查 + 构建前端到 dist/
npm run start        # 后端 3001 同时托管前端
```

浏览器访问 `http://localhost:8000`（开发）或 `http://localhost:3001`（生产）。

## 使用流程

1. **系统设置**：填 SMTP（服务器/端口/SSL/发件邮箱/授权码），发一封测试邮件确认可用
2. **工资发送 → 导入**：拖入 `.xlsx/.xlsm/.csv`；若姓名/邮箱列识别不对，在下方下拉框改列后「重新解析」
3. **预览**：点某一行的「预览」，看到的就是收件人实际收到的邮件
4. **发送**：勾选人员 → 「发送所选」→ 确认 → 实时进度；单个出错时直接点该行「发送」
   - 已发送成功的人默认跳过，需要重发勾选「强制重发」
   - 「选中失败」可一键挑出所有失败的人重发
   - 状态徽章悬停可看发送时间
5. **发送日志**：查看/搜索每次发送结果，可导出 CSV

## 发送状态：重新导入 / 重启后依然在

发送结果存在 `server/data/db.json`，匹配的是**人**而不是表：

- 键：有工号先用**工号**，否则用**姓名 + 邮箱**（不再包含工作表名）
- 所以「重新导入工资表」「改了工作表名」「重启服务」后，已发送的人仍显示 **已发送**
- **跨月不继承**：表名里能识别出月份且不一致时（10 月 → 11 月）状态归零，避免误以为发过
- 想强制重发：勾选「强制重发」；想清空状态：清掉日志或「清空已导入数据」后重新导入

## 界面展示规则

- 「当前表格：xxx.xlsx · 导入时间」只在 **工资发送** Tab 页下方显示，其它 Tab 不出现

## 导入工资表：列名自动识别

导入时**不需要手工选列**，系统按表头关键字自动识别：

| 用途 | 匹配的表头关键字 | 找不到时 |
| --- | --- | --- |
| 姓名 | 姓名 / 名字 / 员工姓名 | 退回第 1 列并提示 |
| 工号 | 工号 / 员工号 / 员工编号 / 编号 | 视为无工号 |
| 邮箱 | 邮箱 / 邮件 / e-mail | **不用邮箱列，全部按通讯录匹配** |

导入后会显示识别结果（`已自动识别：姓名列「姓名」· 工号列「工号」· 邮箱列「无 → 全部按通讯录匹配」`）；万一识别错了，点「手动指定列」展开下拉改完再「重新解析」。

## 通讯录维护（列顺序 / 导出 / 重新导入）

- **列顺序跟随表格**：通讯录列表按你 Excel 里的表头顺序显示（工号在第一列就是第一列），表里多出来的列（入职日期、岗位…）也会保留
- **标题显示来源**：员工管理页标题显示「当前通讯录：文件名（导入时间）」，一眼看出现在用的是哪份表
- **导出 → 改 → 重新导入**：点「导出通讯录」拿到 Excel，改完再导入即可；按**工号**（没有工号时按姓名）定位已有人员做覆盖更新，**不会产生重复**。表里没写「在职」列时不会改动该字段
- **表格里已删掉的人怎么处理**（下拉选择，会记住上次选择）：
  - `sync-disable`（默认）→ 标记为**停用**，不参与工资表匹配，可随时改回
  - `sync-delete` → 直接**删除**
  - `merge` → 保留不动（增量更新）
  - 安全兜底：表格里某人**邮箱被清空**时只跳过不更新，不会把他当成"已删除"而误删
- **改动自动写回 Excel**：界面上新增 / 编辑 / 删除员工，都会立刻同步到本地通讯录表格（默认 `server/data/通讯录.xlsx`）。想同步到你自己的文件，在「同步的表格」输入框里粘贴完整路径（如 `D:\人事\通讯录.xlsx`）点「绑定并同步」即可
  - 只改通讯录工作表的数据行，**其它工作表和原有格式保持不变**；按工号（无工号时按姓名）定位行，新增的追加在末尾，删掉的人对应行也会移除
  - 表格正被 Excel 打开时会写不进去：数据照常保存，界面会红字提示，关掉文件点「立即同步」补上

## 配置

- 页面「系统设置」可改；也可在 `.env` 里配置（优先级更高）：`PORT`、`WEB_PASSWORD`（留空不启用登录）、`SESSION_SECRET`、`SMTP_HOST/PORT/SECURE/USER/PASS`
- 前端端口在 `vite.config.ts` 的 `server.port`（当前 8000），`/api` 代理到后端
- 运行时数据落在 `server/data/`（已 gitignore）：
  - `settings.json` —— 设置
  - `db.json` —— 员工、发送日志、通讯录、**通讯录同步文件路径**、最近导入的文件名
  - `通讯录.xlsx` —— 通讯录同步文件的默认位置（可在界面上改成自己的文件）
