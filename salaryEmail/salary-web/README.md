# 工资条发送系统（Vue 3 + Node/Express + TypeScript）

浏览器里完成「导入工资表 → 预览 → 批量/单个发送 → 发送留痕」的全流程。

## 快速开始

Windows 最简单：双击 **`启动调试.bat`**（开发模式）

- 自动读配置里的端口（不写死）、自动装依赖、起服务、8 秒后自动打开浏览器
- 关掉窗口即停止；改代码前后端都会自动生效

命令行：

```bash
cd salary-web
npm install          # 安装依赖
npm run dev          # 开发模式：前端 + 后端一起起
```

端口从配置读取，改哪边都行：

| 服务 | 端口来源 | 当前值 |
| --- | --- | --- |
| 前端 | `package.json` 里 `vite --port` → `vite.config.ts` 的 `server.port` → 5173 | **8000**（见 `vite.config.ts`） |
| 后端 | `.env` 里的 `PORT=` → 环境变量 `PORT` → 3001 | **3001** |

正式使用（单进程、构建后托管）：

```bash
npm run build        # 类型检查 + 构建前端到 dist/
npm run start        # 后端 3001 同时托管前端
```

浏览器访问 `http://localhost:8000`（开发）或 `http://localhost:3001`（生产）。

## Docker 一键运行

Windows：双击 **`一键Docker启动.bat`**（自动检测 Docker、构建镜像、起容器、打开浏览器）。

命令行：

```bash
cd salary-web
docker compose up -d --build     # 构建并后台启动
docker compose logs -f           # 看日志
docker compose down              # 停止并删除容器
```

- 访问 `http://localhost:3001`
- 端口只有 `.env` 一个来源：`APP_PORT=8080` → 容器内外一起变，访问 `http://localhost:8080`；只想换浏览器访问的端口则写 `WEB_PUBLISH_PORT=8080`（容器内不变）
- 单容器同时提供后端接口与前端页面（生产模式下前端是后端托管的 `dist/`，没有 vite dev server，所以 `WEB_PORT=8001` 只对 `npm run dev` 有效）
- 想改配置：在本目录建 `.env`（`docker compose` 会自动读取）——`APP_PORT`、`WEB_PUBLISH_PORT`、`WEB_PASSWORD`、`SMTP_HOST/PORT/SECURE/USER/PASS`；页面「系统设置」里改的仍然生效，`.env` 优先级更高
- 数据持久化：`./server/data` 挂进容器，`settings.json` / `db.json` 删容器不丢；换数据卷见 `docker-compose.yml` 注释
- 定时发送：容器时区已固定为 `Asia/Shanghai`，配置存 `db.json`，只要容器 `restart: unless-stopped` 就会持续运行

## 使用流程

1. **系统设置**：填 SMTP（服务器/端口/SSL/发件邮箱/授权码），发一封测试邮件确认可用
2. **工资发送 → 导入**：拖入 `.xlsx/.xlsm/.csv`，导入后直接显示表格里的列与自动识别结果（姓名/邮箱/工号列识别不对时，在「系统设置」改默认列名后重新导入）
3. **预览**：点某一行的「预览」，看到的就是收件人实际收到的邮件
4. **发送**：勾选人员 → 「发送所选」→ 确认 → 实时进度；单个出错时直接点该行「发送」
   - 已发送成功的人默认跳过，需要重发勾选「强制重发」
   - 「选中失败」可一键挑出所有失败的人重发
   - 状态徽章悬停可看发送时间
5. **发送日志**：查看/搜索每次发送结果，可导出 CSV

## 发送状态：重新导入 / 重启后依然在

发送结果存在 `server/data/db.json`，匹配的是**人**而不是表：

- 键：有工号先用**工号**，否则用**姓名 + 邮箱**（不再包含工作表名）
- 所以「重新导入工资表」「改了工作表名」「重启服务」后，已发送的人仍显示 **已发送**
- **跨月不继承**：表名里能识别出月份且不一致时（10 月 → 11 月）状态归零，避免误以为发过
- 想强制重发：勾选「强制重发」；想清空状态：清掉日志或「清空已导入数据」后重新导入

## 发送前体检

导入后在「工资发送」页会看到体检卡片，点「发送」时弹窗里也会再列一遍：

| 级别 | 检查项 | 处理 |
| --- | --- | --- |
| 必须处理 | 没有导入数据；有人没邮箱；邮箱格式不对 | 弹窗里要勾选「我已知悉上述问题，仍要发送」才能发 |
| 请留意 | 多人共用同一邮箱；重复人员记录；实发为 0；存在负数金额；人数/合计与上期差异过大（>20% / >30%） | 只提示，不阻断 |

- 每次导入会记一份当月快照（人数、实发合计），下次导入时用它做环比，防止导错月份的表
- 体检只做检查、不改数据；接口 `GET /api/check`

## 定时发送

「工资发送」页底部的「定时发送」卡片：

- 设定「每月 **几号**（或最后一天）**几时几分**」，到点自动把**当前工资表里所有人**发一遍
- 发送前先跑一次体检：有问题时按「体检不通过时」的选项决定**取消发送**（默认，推荐）还是照常发
- 「跳过已发送成功的人」默认开启，避免重复打扰；关掉等于强制重发
- 「立即执行一次」= 按当前配置立刻跑一遍（用来验收配置）
- 配置、上次运行时间、上次结果都存 `server/data/db.json`，重启不丢

两个前提：

1. **服务必须一直开着**：关掉窗口/关机就不会发。建议把 `启动调试.bat` 的快捷方式放进 `shell:startup`
2. **错过不补发**：开机时若已超过计划时间 1 小时以上，会跳过这次并记录原因，不会半夜狂发

接口：`GET/PUT /api/schedule`、`POST /api/schedule/run`（立即执行）

## 导入工资表：列名自动识别

导入时**不需要手工选列**，系统按表头关键字自动识别：

| 用途 | 匹配的表头关键字 | 找不到时 |
| --- | --- | --- |
| 姓名 | 姓名 / 名字 / 员工姓名 | 退回第 1 列并提示 |
| 工号 | 工号 / 员工号 / 员工编号 / 编号 | 视为无工号 |
| 邮箱 | 邮箱 / 邮件 / e-mail | **不用邮箱列，全部按通讯录匹配** |

导入后直接列出**表格里的全部列**，并把识别为姓名 / 工号 / 邮箱的列标出来（`姓名「姓名列」· 工号「工号列」· 实发总计 …`），下面一行是「用于匹配：姓名列「姓名」· 工号列「工号」· 邮箱列「无 → 全部按通讯录匹配」」；列识别完全自动，识别不准时在「系统设置」里改默认列名后重新导入。

## 通讯录维护（列顺序 / 导出 / 重新导入）

- **列顺序跟随表格**：通讯录列表按你 Excel 里的表头顺序显示（工号在第一列就是第一列），表里多出来的列（入职日期、岗位…）也会保留
  - **不显示「在职」列**：列表列 = 你表格里的列。表格里的「在职 / 状态」列**不会**显示（它是系统内部状态 `active`，只用来决定谁参与工资表邮箱匹配，例如「表格里没有的人 → 停用」后就不再匹配）
- **标题显示来源**：员工管理页标题显示「当前通讯录：文件名（导入时间）」，一眼看出现在用的是哪份表
- **改动就在 Excel 里做，然后重新导入**：按**工号**（没有工号时按姓名）定位已有人员做覆盖更新，**不会产生重复**。表里没写「在职」列时不会改动该字段
- **表格里已删掉的人怎么处理**（下拉选择，会记住上次选择）：
  - `sync-disable`（默认）→ 标记为**停用**，不参与工资表匹配，可随时改回
  - `sync-delete` → 直接**删除**
  - `merge` → 保留不动（增量更新）
  - 安全兜底：表格里某人**邮箱被清空**时只跳过不更新，不会把他当成"已删除"而误删
- **只读**：界面只做**导入 + 查看**（搜索 / 只看在职），**不提供新增、编辑、删除，也不回写或导出 Excel**
- **维护方式**：财务在 Excel 里维护通讯录，有人员变动就**重新导入**同一张表（按工号 / 姓名覆盖，不会产生重复）
- **表格里已删掉的人怎么处理**（下拉选择，会记住上次选择）：删除 / 停用 / 保留不动（见上）

## 配置

- 页面「系统设置」可改；也可在 `.env` 里配置（优先级更高）：`PORT`、`WEB_PASSWORD`（留空不启用登录）、`SESSION_SECRET`、`SMTP_HOST/PORT/SECURE/USER/PASS`
- 前端端口在 `vite.config.ts` 的 `server.port`（当前 8000），`/api` 代理到后端
- 运行时数据落在 `server/data/`（已 gitignore）：
  - `settings.json` —— 设置
  - `db.json` —— 员工、发送日志、通讯录、最近导入的文件名
