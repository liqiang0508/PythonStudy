# 工资条发送系统 — 需求与实现技术方案

> 版本：v1.1　日期：2026-10-14　技术栈：**Vue 3 + TypeScript + Vite（前端） / Node + Express + TypeScript（后端）**
> 前置：已有一个 Python 命令行版 `sendSalaryEmail.py`（可用，保留作为脚本备用）
>
> v1.1 增补：员工通讯录**双向同步本地 Excel**、发送状态**按人持久化**（跨重新导入/重启）、上传**中文文件名修复**、界面展示范围收拢、`启动调试.bat`（端口自动识别 + 自动开浏览器）。详见 §3.5、§3.7、§5。

---

## 一、背景与目标

财务/HR 每个月要发工资条，现有 Python 脚本存在几个痛点：

- 需要改 `CONFIG.json`、敲命令行，财务人员不会用
- 发之前看不到每个人收到的邮件长什么样
- 某人发错了只能整体重跑一遍，容易重复发送
- 发送结果没有留痕，谁成功谁失败靠记忆
- 授权码明文写在配置文件里

**目标**：做一个浏览器里点点鼠标就能完成的「工资条管理 + 发送系统」，覆盖 **导入 → 预览 → 批量/单个发送 → 留痕** 全流程，且工资数据不外泄。

## 二、需求清单

### 2.1 角色与场景

| 角色 | 场景 |
| --- | --- |
| HR / 财务 | 每月导入工资表，核对后批量发送；个别人出错后单独重发 |
| 管理者 | 查看发送记录，确认全部送达 |

### 2.2 必备功能（P0）

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| F1 | **导入表格** | 支持 `.xlsx / .xlsm / .csv`，支持拖拽上传；自动识别表头行、跳过空行 |
| F2 | **列映射** | 默认按表头名匹配「姓名」「邮箱」列；匹配不到时页面上可下拉手动指定，无需改文件重新上传 |
| F3 | **预览** | 列表页点「预览」弹窗展示该员工实际收到的邮件样式（HTML 渲染，1:1 效果） |
| F4 | **批量发送** | 勾选多人 → 二次确认 → 实时进度条 → 结果汇总 |
| F5 | **单个发送** | 列表行内直接「发送」，用于某人工资算错后修正重发 |
| F6 | **SMTP 设置** | 页面配置服务器/端口/SSL/账号/授权码/发件人名/主题模板，可发测试邮件验证 |
| F7 | **发送日志** | 每次发送均记录时间、姓名、邮箱、成功/失败、失败原因；支持导出 CSV |
| F8 | **导入模板** | 提供标准模板下载，避免表头格式不对 |

### 2.3 增强功能（P1，建议一起做）

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| F9 | **防重复发送** | 列表显示每人「未发送 / 成功 / 失败」状态；批量发送默认跳过已成功的人，可勾选「强制重发」 |
| F10 | **只发失败的人** | 一键筛选失败项并重试（对应 Python 版的 `--retry-failed`） |
| F11 | **搜索与筛选** | 按姓名/邮箱搜索，按工作表、发送状态筛选 |
| F12 | **发送节流与重试** | 每封间隔可配（默认 1s），失败自动重试 2 次，避免被邮件服务商限流/判垃圾邮件 |
| F13 | **密送留档** | 可配置 BCC（如 HR 邮箱），自动留底 |
| F14 | **任务可取消** | 批量发送进行中可中止 |
| F15 | **访问密码** | 可选登录保护，未登录不能访问任何接口 |
| F16 | **数据校验提醒** | 邮箱为空/格式错误的人高亮并禁止发送；重复邮箱警告 |
| F17 | **多工作表** | 一个文件多个 sheet 全部解析，sheet 名带入邮件主题 |
| F18 | **清空数据** | 一键清除已导入的工资数据（换月/误导入） |
| F19 | **员工通讯录** | 员工档案（姓名/邮箱/工号/部门/在职状态/备注）的增删改查 + 从表格批量导入 |
| F20 | **按姓名自动匹配邮箱** | 工资表**不需要邮箱列**：导入时按姓名从通讯录取邮箱；匹配不到可手动绑定 |
| F21 | **同名用工号区分** | 通讯录允许同名，但同名者必须有不同的工号；匹配时按「姓名 → 同名用工资表工号 → 姓名错时用工作号兜底」三级规则；仍无法确定则提示手动指定 |
| F22 | **通讯录写回 Excel** | 界面上新增/编辑/删除员工，自动同步到本地通讯录表格（可绑定用户自己的 `.xlsx/.csv`）；只改数据行，其它工作表与格式保留 |
| F23 | **发送状态持久化** | 状态按「工号 → 姓名+邮箱」匹配，重新导入工资表、改工作表名、重启服务后仍显示已发送；跨月（10 月 → 11 月）自动归零 |
| F24 | **中文文件名修复** | 上传文件名不再乱码（busboy latin1 误解码），历史乱码数据在读取时自动还原 |

### 2.4 非功能需求

- **安全**：授权码不明文返回前端（掩码显示）、支持环境变量注入；可选登录；数据只存本机
- **易用**：全流程不超过 4 次点击；错误提示为中文人话
- **性能**：200 人以内批量发送流畅，页面不卡死（后端异步任务 + 前端轮询进度）
- **兼容**：Chrome/Edge 最新版；服务端 Node ≥ 18

### 2.5 本期不做

多人协作/多账号、工资条 PDF 附件、员工自助查询 portal、历史月份归档对比、钉钉/企业微信推送。

## 三、技术方案

### 3.1 总体架构

```
浏览器 (Vue 3 + TS)
   │  HTTP /api/*
   ▼
Express (TS)  ──► exceljs   解析工资表
   │           ──► nodemailer  SMTP 发送（连接复用）
   │           ──► JSON 文件存储（server/data/db.json）
   ▼
SMTP 服务器（QQ/企业邮箱/Exchange）
```

单机部署：后端同时托管前端静态资源，`npm run start` 一个进程搞定，财务电脑上双击启动脚本即可。

### 3.2 技术选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 前端框架 | **Vue 3 (`<script setup>` + TS)** | 你指定；单文件组件，模板直观，上手快 |
| 构建 | **Vite 6** | 启动快、配置少，dev 代理 `/api` 到后端 |
| 后端 | **Node + Express 4 + TS（tsx 运行）** | 与前端同一语言；无需编译步骤，`tsx` 直接跑 TS |
| 邮件 | **nodemailer** | Node 生态事实标准；支持连接池、SSL/STARTTLS |
| Excel | **exceljs** | 纯 JS 无原生依赖，支持 xlsx/csv，避免 node-gyp 编译问题 |
| 存储 | **JSON 文件（server/data/）** | 数据量小（几百条），零依赖；SQLite 需原生模块，暂不引入 |
| 上传 | **multer（内存模式）** | 文件不入磁盘，减少工资数据残留 |

> 说明：浏览器无法直接发 SMTP 邮件，因此「纯前端」不可行，必须有一个轻量后端；后端仍用 TS，保持全栈 JS/TS。

### 3.4 数据模型（`shared/types.ts`）

```ts
interface SalaryItem { key: string; value: string; bold: boolean }   // 一行工资项

interface Employee {
  id: string; sheet: string; name: string; email: string
  valid: boolean          // 邮箱格式是否合法
  items: SalaryItem[]
}

interface EmployeeSummary {            // 列表用，不含明细，减少传输
  id: string; sheet: string; name: string; email: string
  valid: boolean; total: string        // 实发金额，便于核对
  lastStatus: 'success' | 'failed' | null
  lastError?: string; lastTime?: string  // 上次发送结果/时间
  empNo?: string; emailSource?: EmailSource
}

interface LogEntry {
  id: string; time: string; batchId: string
  sheet: string; name: string; email: string
  empNo?: string                        // 便于改名/换邮箱后仍认得出人
  status: 'success' | 'failed'; error?: string
}

interface Contact {                    // 员工通讯录
  id: string; name: string; email: string; empNo: string
  department: string; active: boolean; note: string
  extra?: Record<string, string>        // 表格里的自定义列，导出时原样带回
}

interface SyncState {                  // 通讯录写回 Excel 的结果
  ok: boolean; file: string; error?: string
  added?: number; updated?: number; removed?: number
}

interface Settings {
  smtpHost: string; smtpPort: number; secure: boolean; allowInsecureTLS: boolean
  smtpUser: string; smtpPass: string          // 仅存服务端，接口返回时掩码
  senderName: string; subjectTemplate: string // 支持 {sheet} {name} 占位符
  bcc: string; retry: number; delayMs: number
  nameColumn: string; emailColumn: string
  useContacts: boolean                 // 用通讯录匹配邮箱
  empNoColumn: string                  // 工资表工号列名，用于同名区分
}

interface JobStatus {                          // 发送任务进度
  id: string; state: 'running' | 'done' | 'cancelled'
  total: number; done: number; success: number; failed: number; skipped: number
  results: { id: string; name: string; email: string; ok: boolean; skipped?: boolean; error?: string }[]
}
```

### 3.5 关键流程

**导入**
1. multer 内存接收文件 → `exceljs` 载入
2. 找第一行非空单元格作为表头行；`<b>xxx</b>` 表头视为分组/加粗行
3. 按 `nameColumn/emailColumn` 定位列（精确 → 包含 → 退回第 1/2 列并给出警告）
4. 逐行生成 `Employee`，跳过全空行；邮箱正则校验；数值千分位格式化
5. 员工写入 store；列识别全自动（姓名 / 邮箱 / 工号），识别不准时在「系统设置」改默认列名后重新导入
6. 返回摘要 + 警告（未匹配列、重复邮箱、无数据等）

**发送**
1. 前端提交 `{ ids, force }` → 后端建任务返回 `jobId`，立即返回不阻塞
2. 后端异步循环：`已成功且非强制 → 跳过` → 渲染 HTML/纯文本 → `transport.sendMail` → 失败重试 N 次（重连）→ 间隔 `delayMs`
3. 每完成一人更新 `JobStatus` 并写一条日志
4. 前端轮询 `GET /api/job/:id`（600ms）展示进度条与实时结果，可取消

**预览**
`GET /api/employees/:id/render` 返回渲染后的 HTML 字符串，前端用 `<iframe :srcdoc>` 展示，与真实邮件完全一致（同时提供纯文本兜底，降低进垃圾箱概率）。主题里已含月份时，正文副标题只显示姓名，避免月份重复出现两次。

**状态匹配（v1.1）**
1. 日志落库时额外记 `empNo`
2. 查某人上次结果：`工号` → `姓名 + 邮箱`（都不再包含工作表名）
3. 表名里能识别出月份且两边不一致 → 视为新一期，不继承状态
4. 因此重新导入 / 改表名 / 重启都不丢状态；换月自动归零

**通讯录写回 Excel（v1.1）**
1. 打开同步文件（默认 `server/data/通讯录.xlsx`，可绑定用户自己的路径）→ 定位「通讯录」工作表与表头行
2. 按 **工号**（无工号按姓名）定位数据行 → 覆盖姓名/邮箱/工号/部门/备注/在职/自定义列；不由通讯录维护的列保持原值
3. 表里没有的人追加到末尾；界面删掉的人对应行移除（自下而上 `spliceRows`，行号不串）
4. 其它工作表与原有格式保持不动；`.csv` 走单独分支（UTF-8 BOM）
5. 文件被 Excel 独占时写不进去：数据照常入库，返回 `sync.ok=false` 与原因，前端红字提示，可点「立即同步」补写

**上传文件名（v1.1）**
multer/busboy 把 UTF-8 文件名按 latin1 解码，中文会变 `2026å¹´10æ...`。上传时用 `Buffer.from(name,'latin1').toString('utf8')` 还原；`db.json` 里的历史乱码值在加载时按「码点全部 ≤ 0xFF」判定后自动还原。

### 3.7 前端页面

- **顶部**：系统名 + 一句说明 + 登录状态（**不显示**导入的文件名）
- **Tab 1 工资发送**：Tab 正下方显示「当前表格：xxx.xlsx · 导入时间」→ 导入区（拖拽/选择）→ 工具栏（搜索、状态筛选、全选、只选失败）→ 员工表格（勾选 / 姓名 / 邮箱 / 来源 / 工作表 / 实发 / 状态徽章 / 预览 / 发送 / 补邮箱）→ 底部「发送所选 N 人」
- **Tab 2 发送日志**：时间、姓名、邮箱、结果、失败原因，导出 CSV
- **Tab 3 员工管理**：标题显示「当前通讯录：xxx.xlsx（导入时间）」→ 搜索 / 只看在职 / 新增 / 导入 / 导出 / 同步表格（绑定路径、立即同步、打开文件位置）→ 通讯录表格（列顺序与 Excel 一致，行内编辑/删除）
- **Tab 4 设置**：SMTP 表单 + 「发送测试邮件」+ 主题模板/密送/间隔/重试/列映射默认值
- **弹窗**：预览（iframe）、发送确认（人数、发件人、强制重发勾选）、进度（进度条 + 实时成功/失败清单）

### 3.8 邮件渲染规则

- 表格化卡片布局：项目名左、金额右对齐等宽数字
- 数值：整数千分位；小数保留两位
- 表头含 `<b>` 或关键字（`合计/实发/应发/总计`）→ 加粗 + 浅底；空值且为分组表头 → 渲染成小标题（如「减」）
- 空值项不展示，避免工资条出现一堆 `0`
- 尾部固定免责与异议反馈说明
- 主题：`subjectTemplate`，支持 `{sheet}`、`{name}`

## 四、安全设计

1. **授权码**：接口返回一律掩码 `••••••••`；保存时若前端回传掩码则保留原值；支持 `.env` 注入，优先级高于页面配置
2. **登录保护**：`WEB_PASSWORD` 非空时启用；HttpOnly + SameSite=Lax 签名 Cookie（HMAC + 随机密钥），未登录访问 API 返回 401
3. **数据落地**：工资数据只写本机 `server/data/`（已 gitignore），上传文件仅内存处理不落盘
4. **日志脱敏**：日志只记录姓名/邮箱/结果，不记录工资金额
5. **发送保护**：默认跳过已成功人员；批量发送必须二次确认；可配置密送留档

## 五、运行与部署

```bash
cd salary-web
npm install
cp .env.example .env        # 按需填写 WEB_PASSWORD / SMTP_*
npm run dev                 # 开发：前端（端口取自 vite.config.ts，当前 8000）+ 后端 3001
npm run build               # 类型检查 + 打包到 dist/
npm run start               # 生产模式：后端 3001 同时托管前端
```

**端口不是写死的**：

| 服务 | 读取顺序 |
| --- | --- |
| 前端 | `package.json` 中 `dev:web` 的 `--port` → `vite.config.ts` 的 `server.port` → 5173 |
| 后端 | `.env` 的 `PORT=` → 环境变量 `PORT` → 3001 |

**`启动调试.bat`**（Windows 双击即可，推荐本地调试用）：

1. 切到脚本所在目录 → 检查 Node
2. 用 `node scripts/dev-ports.mjs` 读出真实端口并打印两个网址
3. 缺 `node_modules` 时自动 `npm install`
4. 后台轮询前端端口，监听成功后自动 `start http://localhost:<port>`（最多等 40 秒）
5. 前台运行 `npm run dev`，关窗口即停

启动后浏览器打开 `http://localhost:8000`（开发）或 `http://localhost:3001`（生产）。
若要给财务当「软件」用：再加一个生产模式启动脚本（`npm run start` + 自动开浏览器）；后续可再用 `pkg`/`nexe` 打成 exe 或做成 Windows 服务。

## 七、风险与注意事项

1. **`.xls` 老格式**：exceljs 不支持二进制 `.xls`，遇到时提示「请另存为 .xlsx」；CSV 需 UTF-8 编码，Excel 直接导出的 GBK CSV 会乱码
2. **SMTP 限流**：QQ 邮箱等对个人邮箱有频率限制，间隔与重试参数可调；企业邮箱建议用企业 SMTP
3. **数据规模**：JSON 存储适合 ≤ 数千条；更大体量再换 SQLite
4. **并发**：系统为单机单用户设计，不建议多人同时导入
5. **Python 脚本**：继续保留，作为命令行/定时备份方案，两套逻辑保持渲染规则一致
6. **通讯录同步文件被占用**：Excel 打开该文件时写不进去（Windows 独占锁），此时数据仍入库，界面红字提示，关闭后点「立即同步」补写
7. **同步会覆盖文件**：绑定的 Excel 以界面数据为准被重写，绑定前建议先备份；只改「通讯录」工作表的数据行
8. **端口占用**：前端端口被占用时 Vite 会自动换端口，此时 `启动调试.bat` 的自动开浏览器可能打不开，看窗口提示的网址即可

### 员工通讯录（F19~F21）补充设计

- **数据**：`Contact { id, name, email, empNo, department, active, note }`，与工资数据同存 `server/data/db.json`，新增通讯录接口 `/api/contacts*`
- **匹配规则（最终版）**：工资表**可以不写邮箱列**（设置里把「默认邮箱列名」留空即可）。`useContacts` 开启时按三级规则匹配：
  1. 按**姓名**在通讯录里找，唯一命中 → 采用
  2. 同名多人 → 用工资表里**工号列**（列名在设置里配）的值，在同名者中找工号一致的那个
  3. 姓名没匹配上（改名/错字）→ 用**工号**在通讯录里兜底找
  命中 → `emailSource='contact'`；未命中 → 回落表格自带邮箱（`sheet`，若有）或标记未匹配（`none`）
- **同名规则**：通讯录**允许同名**，但同名者必须填不同的工号（新增/编辑接口会校验）；同名且无工号 → 不自动匹配，导入告警提示手动指定
- **手动兜底**：列表「补邮箱」弹窗可从通讯录点选或直接填邮箱（`manual`）；通讯录补全后点「用通讯录重新匹配」批量重刷
- **停用**：`active=false` 的员工不参与匹配（离职不用删档案，保留历史）
- **已验证**：工资表不含邮箱列（邮箱列名留空）→ 按姓名匹配成功；两个同名「张三」（工号 E001/E002）按工号分别匹配到不同邮箱；姓名写错（王五 + 工号 E003）按工号兜底命中；无工号列时同名 → 告警「通讯录中存在重复人员，已跳过自动匹配，请手动指定：张三」并标记未匹配；手动绑定（manual）→ 补录通讯录后重新匹配（contact）
